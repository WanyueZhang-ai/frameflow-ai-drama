# 可视化记忆与场景补全

## 在工作台中使用

1. 打开「项目记忆 → 场景与空间」，选择要编辑的剧本场景。新项目可以先设置第一个场景，再生成剧本。
2. 选择便利店、咖啡馆、办公室或客厅模板。模板是人工编写的建议，不是从上传图片中自动识别的结果。切换模板只替换草稿中的元素。
3. 逐项勾选背景，区分「剧情必需」「固定背景」「氛围细节」。可以添加自己的元素，点击布局中的物体后用滑块调整位置。
4. 选择补全方式：「仅明确内容」「按我的选择」或「有限自由补全」。已勾选元素始终是明确设定；自由补全仅允许不改变剧情的装饰。
5. 设置场景基准机位、角色站位、天气、光线及场景起止状态。镜头编辑器还可单独选择机位，用于反打等不同视角。参考图可选，支持 500 KB 以内 JPG / PNG / WebP。
6. 展开生成约束预览，检查将用于相关镜头的内容，点击「保存并用于生成」。草稿在当前页面内保留；未保存的草稿不参与生成，刷新后丢弃。

保存场景、角色或风格会重置分镜、视频、配音、合成和审批状态，保留已有剧本与审稿。下一次运行从待执行阶段继续。重新运行整个已完成项目和切换生成模式会继承已保存设定。编辑剧本时按场景 ID 关联已有场景设定，删除的场景不再传递。若场景 ID 被用于不同地点，请重新检查对应布局。

「角色与风格」可编辑固定外观和声线描述。用户编辑的外观优先于下一次编剧生成的旧描述。声线仍是创作设定，当前 TTS 使用服务中配置的统一音色。「事实与时间线」展示剧本事实、场景起止状态、设定版本、来源和工作流摘要。

## 数据与生成链路

`dist/lib/memory.mjs` 是浏览器和服务端共用的数据层：

- `ensureMemory` 将原有 characters/style/facts/summaries 迁移到 schema v2，不自动添加背景物体。
- `syncScriptMemory` 将剧本场景与角色同步到记忆，保留同 ID 场景以及用户编辑的角色设定。
- `commitScene` 保存已选择的元素、环境、机位、角色站位、起止状态及参考图，并递增版本、记录来源。
- `memoryContext` 为语言模型提供结构化记忆，移除图片 Base64，图片另以带场景 ID 的多模态内容传递。
- `compileStoryboard` 给每个镜头附加场景约束和 `shotSpec`，包含场景版本、记忆版本、必要元素和固定背景 ID。
- `videoInput` 在提交前重新编译约束，场景参考图优先于项目公共参考图。每镜头仍只向现有视频协议提交一张图片。
- 视频检查点记录请求指纹，提示词、画幅、时长或参考图变化会使用不同的任务幂等键。供应商已明确失败后的重新提交会增加尝试版本。

提示词编辑器只编辑镜头本身的描述；场景约束从记忆重新附加，避免重复追加旧版本约束。场景起止状态属于整场戏，模型需要按镜头剧情进展分配，不应在每个镜头重复整个事件。

## 空间语义与边界

布局使用归一化平面坐标，北在上、南在下，横纵位置范围为 8–92。坐标表达场景中的位置，不等同于每个机位的画面位置。机位为四个方向的示意，没有镜头内参、透视投影、真实尺度或三维重建。

这些约束会编入文本提示词；布局 SVG 不会被伪装成后端支持的深度或相机控制信号。场景参考图是图片条件，不保证生成模型遵循。应使用已配置、支持多图输入的视觉模型读取场景参考图。

生成请求成功只表示服务返回媒体。所有镜头规范的 `verification` 都保留为 `unverified`，不会自动把生成结果写成已验证事实。当前时间线展示创作要求，没有声称已从视频观测中确认这些状态。自动抽帧、视觉验收和局部修复循环仍需后续接入。

浏览器项目继续保存在本机 localStorage；图片受浏览器存储额度限制，建议导出 JSON 备份。未保存草稿不进入 JSON。API Key 的存储与传输规则保持原有实现。

## 验证

`npm test` 覆盖旧项目迁移、草稿隔离、版本来源、剧本同步、约束替换、场景参考图绑定、完整重跑、服务端导入、浏览器与服务端视频请求、请求变更和失败重试幂等键。`npm run check` 检查模块语法和静态资产。
